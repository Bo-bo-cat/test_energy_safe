# Contributing Guide
 
Цей документ описує правила командної роботи з Git. Прочитай перед тим, як починати розробку.
 
---
 
## Гілки
 
| Гілка         | Призначення                                                   |
|---------------|---------------------------------------------------------------|
| `main`        | Тільки стабільний робочий код. **Пушити напряму заборонено.** |
| `dev`         | Основна гілка розробки. Всі мерджать сюди.                    |
| `feature/xxx` | Нова функціональність, наприклад `feature/pilot-profile`      |
| `fix/xxx`     | Виправлення помилки, наприклад `fix/login-error`              |
 
---

## Як працювати з гілками
 
```bash
# 1. Переконайся, що ти на актуальному dev
git checkout dev
git pull origin dev
 
# 2. Створи нову гілку від dev
git checkout -b feature/назва-фічі
 
# 3. Роби зміни, комітай
git add .
git commit -m "feat: опис що зробив"
 
# 4. Запуш гілку
git push origin feature/назва-фічі
```
 
---
 
## Як робити Pull Request
 
1. Створи гілку від `dev`
2. Зроби роботу, закомітай зміни
3. Відкрий PR у гілку `dev` (не в `main`)
4. Попроси когось з команди переглянути
5. Мердж — тільки після підтвердження (approve) від іншого члена команди
6. Після мерджу — видали свою гілку

---
 
## Стиль комітів
 
Використовуємо [Conventional Commits](https://www.conventionalcommits.org/):
 
```
feat: додав сторінку профілю
fix: виправив помилку реєстрації
chore: оновив залежності
docs: оновив README
refactor: переписав логіку авторизації
style: відформатував код
test: додав тести для логіну
```

## Вирішення конфліктів
 
Якщо при мерджі є конфлікти:
 
```bash
git checkout dev
git pull origin dev
git checkout feature/твоя-гілка
git merge dev
# Вирішуй конфлікти, потім
git add .
git commit -m "chore: merge dev into feature/назва"
```

---
 
## Чеклист перед PR
 
- [ ] Код працює локально
- [ ] Немає зайвих `console.log` або закоментованого коду
- [ ] Гілка створена від актуального `dev`
- [ ] Назва гілки відповідає конвенції (`feature/` або `fix/`)
- [ ] Коміти написані за стилем
